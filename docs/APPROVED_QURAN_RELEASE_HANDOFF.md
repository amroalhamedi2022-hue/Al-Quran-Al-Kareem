# Safely handing a genuinely approved Quran pack to signed Android releases

**Current status: BLOCKED — no approved content is supplied or inferred by this document.**

## Why this is needed

The source exporter produces 604 PNG files plus `source_provenance_manifest.json` whose status is
`UNAPPROVED_RENDER_ONLY`. A checksum authenticates the export bytes; it **does not**
prove that every Qur'an glyph, mark or line is correct. A signed production APK
may only embed an **independently reviewed** `approved_manifest.json`, which must
match the exported PNGs *byte for byte*. We must not compile a production APK
from the unapproved page pack and try to insert the approval afterward.

## Approval source of truth (never fabricated by CI)

After two qualified independent full 604-page comparisons against the original publisher
artwork, resolve every discrepancy, document permissions, verify reviewers' identity
outside CI, and record explicit human signoff. Only THEN create an external
`release-approval/approved_manifest.json`. This manifest is NOT created by the
promotion script, and none currently exists in this repository.

Mandatory fields:

- `source_name`: clearly identify the original publisher and edition.
- `source_url`: publisher provenance URL.
- `source_sha256`: published original AI archive SHA-256, fixed to
  `280c5d71ca16aaeeb3a343be1b92c76fa6df71d0671e202c026fde12402d9eef`.
- `source_report_sha256`: SHA-256 of the exact `source_provenance_manifest.json`
  produced from the 604 PNGs that were **actually** independently reviewed.
- `rights_reviewed`: `true` only when usage rights were checked.
- `riwaya`: `Hafs 'an Asim`; `layout`: `Madinah 604-page`.
- `approved_by`: at least two distinct recorded qualified reviewer identities
  corresponding to genuine off-platform review records (a string alone does not prove this).
- `pages`: 604 ordered records with the *exact* `page`, `file` and `sha256`
  for each independently reviewed original PNG, `001.png` to `604.png`.

No OCR, automatic codepoint correction, re-rendered replacement page, image recompression,
autogenerated approval signatures or AI-created approval records are permitted.

## Cryptographic and packaging chain

1. Pin the **exact SHA-256 of the external independent approved manifest** in
   `QuranAssetVerifier.kt` as `INDEPENDENTLY_APPROVED_MANIFEST_SHA256`.
   This field remains EMPTY until real signoff.
2. The signed-release GitHub workflow downloads and checks original publisher
   artwork (all 604 PNG files) and stages it as `UNAPPROVED_RENDER_ONLY`.
3. **Before Gradle assembles an APK**, run `scripts/verify_approval_seal.py`
   on the independently approved manifest and the pinned Kotlin constant.
4. Run `scripts/promote_approved_quran_pack.py`. It refuses a mismatched
   original archive, conversion report, manifest SHA pin, page ordering, any PNG
   byte/format/size change, missing or extra images, and unreviewed permissions.
   It only replaces the metadata sidecar; PNG bytes stay identical.
5. Run `scripts/verify_quran_pack.py` for the entire approved bundle, then
   compile, sign using the **existing lifetime Android keystore**, and call
   `scripts/verify_release_apk.py` on the actual signed APK against the
   independently approved manifest **outside the APK**.
6. Audit the manifest permissions, APK package ID/signature, complete device
   screenshots and 604-page visual operation in a real emulator and hardware.
   No automated checksum test substitutes for qualified scholarly comparison.

**Fail-closed behavior:** until the external reviewed manifest and its independent
Kotlin SHA pin both exist, the signing workflow errors and releases NOTHING.
A normal debug build for CI with no Quran artwork does not imply a release or
approved Quran content.

## What this change actually proves

It makes a future real approval usable in the **correct build order**, with
source-to-review-to-APK cryptographic checks. It cannot manufacture a review,
verify someone's qualifications or religious accuracy, or approve an existing
unreviewed artifact. Existing `scripts/verify_publisher_release_apk.py` remains a
technical verifier for unapproved publisher-byte artifacts; **production APKs
must use** `scripts/verify_release_apk.py` against the external reviewed manifest.
